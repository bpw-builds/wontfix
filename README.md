# wontfix

A ledger of decisions and dead ends that lives in your repo. Your coding agent writes to it as it works. Claude Code, Cursor and Codex load it back at the start of every session.

```bash
npm install -g wontfix
wontfix init
```

## What it holds

Four kinds of entry. These are real ones, from this repo:

```
wontfix     short handles taken from the id prefix
            reason: the first 8 chars are timestamp-derived, so same-millisecond
                    writes collide and revoke hits the wrong entry

constraint  pass log separators via git's %x1f, node rejects null bytes in spawn args
            reason: spawnSync throws ERR_INVALID_ARG_VALUE on \0 in argv

decision    JSONL, append only, never rewritten
            reason: two agents in two terminals must not corrupt each other

state       auth migration half done, /login is new and /signup is old
```

`--why` is required on `wontfix` and `decision`. A rejection without a reason is a rule nobody can ever overturn.

`wontfix` ranks highest, because it is the type no other tool keeps. `state` ranks lowest and expires after two weeks, because stale state is worse than none.

## What the agent gets

`pack` ranks the ledger and cuts it to a token budget. Real output from this repo, squeezed to 400 tokens to force the cut:

```markdown
## Project context (generated by wontfix)

### Already tried and rejected. Do not propose these again.
- short handles taken from the id prefix. Reason: the first 8 chars are timestamp-derived, so same-millisecond writes collide and revoke hits the wrong entry [src/ledger.js]
- bolting --web onto pack instead of a separate export command. Reason: pack runs on every session start via the hook, so a marker write there makes did-I-export unanswerable

### Rules that must hold.
- web export budget defaults to 600, not 1200. Reason: instructions fields are small and truncation is silent [src/export.js]
- handle EPIPE on stdout in the CLI entry point. Reason: wontfix list | head crashed with a stack trace before this [bin/wontfix.js]

<!-- wontfix: 7 of 10 entries packed. 3 omitted (3 decision). Budget 400. -->
```

The ledger grows without limit. The context does not, and the last line says what was cut.

## Commands

```bash
wontfix add wontfix "<what you tried>" --why "<why it failed>"
wontfix add constraint "<rule>"
wontfix add decision "<choice>" --why "<why>"
wontfix add state "<what is true now>"

wontfix pack                 # the context block
wontfix export --copy        # same block, sized for browser chats
wontfix why "<search>"       # the reason, plus a link to the commit
wontfix list
wontfix stats
wontfix backfill             # propose entries from git history
wontfix revoke <handle>
wontfix hook install|remove|status
```

Add `--durability permanent` for things that outlive the project, `session` for notes that should expire. Add `--scope src/api` to tie an entry to one area.

## Session hooks

`init` writes a session-start hook for three tools:

| Tool | File | Event |
|---|---|---|
| Claude Code | `.claude/settings.json` | `SessionStart` |
| Codex | `.codex/hooks.json` | `SessionStart` |
| Cursor | `.cursor/hooks.json` | `sessionStart` |

Claude Code and Codex share a hook shape and run the same command. Cursor expects `additional_context` rather than `hookSpecificOutput`, so it gets `--format cursor`. Existing hooks are preserved; a config that is not valid JSON is skipped rather than overwritten.

Cursor's `sessionStart` does not fire for cloud agents, and Codex hooks do not run on Windows. Both are upstream limits.

`init` also writes the rules into `AGENTS.md`, which Codex, Cursor, Aider, Jules and Zed read natively. Some repos forbid adding guidance to `CLAUDE.md` or Cursor rules, so those are opt in: `wontfix init --guidance agents,claude,cursor`.

## Browser chats

```bash
wontfix export --copy
```

Puts a block on your clipboard for the instructions field of a Claude Project, ChatGPT project or Gemini Gem. It carries an explicit rule line and defaults to a 600 token budget, since instructions fields are small and truncation is silent.

This direction is read-only. The browser cannot write back, so the pasted block is a cache, and `stats` reports how many entries have landed since you last exported it.

## Whether it is working

The ledger only helps if it fills itself:

```
$ wontfix stats
Entries        13 total, 10 live
Written by     7 agent, 6 human
Agent share    54%
Rate           91.0 per week, 49.0 by agent
Age            1 days since first entry
```

Backfilled entries are tagged `source: git` and excluded from that share, so mining your own history cannot flatter the number.

## Starting from an existing repo

```bash
wontfix backfill
```

Reads reverts, rollbacks and migrations out of git history and prints what it found. Writes nothing until `wontfix backfill --apply`, and drops any candidate whose commit message never said why.

## Storage

`.wontfix/ledger.jsonl`, one JSON object per line, append only, committed so a team shares one memory. Nothing is deleted or rewritten, which keeps `git diff` readable and stops two agents in two terminals corrupting each other.

`wontfix init --private` keeps the ledger out of git, and warns if git already tracks it, since a gitignore line does nothing to a tracked file.

## Security

The ledger arrives through git and is injected into an agent's context, so it is a trust surface.

Handled: entry text is flattened on write and again at render, removing newlines, ANSI escapes, control characters and leading markdown, so an entry cannot forge a section that reads as instructions. Credentials are scrubbed, anchored to recognizable prefixes so ordinary prose survives. No user string reaches a shell. Reads are capped at 16MB. The ledger is written owner only.

Not handled: a merged pull request can add a plausible entry, or append a line reusing an existing id to revoke a real one. Sanitizing text does not make content trustworthy. Review changes to `.wontfix/ledger.jsonl` like changes to CI config. `stats` reports the revocation count so a jump is visible.

## Notes

Agents follow the rules most of the time, not always. When `stats` looks thin, tell the agent to record what it just learned.

A rejection ledger can calcify. Reasons go stale, and the rules tell the agent to challenge an entry whose reason no longer holds rather than obey it.

Token counts are estimated at four characters per token. Zero dependencies, no accounts, no server, no telemetry.

Plain-text project memory for agents is not a new idea; projectmem and Codified Context both explore it. What is specific here is that every rejection carries its reason, context is ranked and budgeted rather than pasted whole, the agent writes entries as a side effect of working, and it travels through git.
